# ADR: 루프 엔지니어링 프로토콜

- 날짜: 2026-09-02
- 상태: 채택

## 목적

넓은 변경을 작은 검증 루프로 나눠, 구현량이 아니라 관측 가능한 제품 동작을 완료
기준으로 삼습니다. 현재 상태는 git, 활성 입력은 `TODO.md`, 장기 결정은 ADR이
각각 소유합니다.

## 루프 계약

각 루프를 시작하기 전에 다음 다섯 항목을 선언합니다.

1. 사용자가 얻는 결과 한 문장
2. 읽을 코드·문서·실제 입력
3. 실행할 검증 명령과 합격 출력
4. 수정과 재검증 최대 3회, 외부 의존 또는 보호 범위 침범 시 중단
5. 건드리지 않는 세션·프로세스·설정·외부 시스템

실행은 `관측 → 최소 재현 → 가설 → 계측 → 수정 → 회귀 테스트` 순서입니다. 같은
실패가 세 번 반복되면 표면 패치를 멈추고 경계와 가정을 다시 설계합니다.

## Maker–checker

작성과 검토는 서로 다른 패스로 수행합니다. checker는 구현 설명이 아니라 사용자
요구, 공개 provider 계약, 실제 런타임 동작을 정본으로 삼습니다. 최종 tree에서
오케스트레이터가 직접 실행한 원시 테스트 출력은 다시 전부 실행하지 않아도 되지만,
검증 뒤 코드가 바뀌거나 보안·파서·동시성 경계를 건드렸다면 표적 테스트를 재실행합니다.

## 완료 게이트

- 선언한 검증이 최종 tree에서 모두 성공합니다.
- `git diff --check`가 성공하고 예상 밖 staged·untracked 파일이 없습니다.
- 실제 provider 검증은 `waga-proof-*` 폐기용 세션에서만 수행하고 정확한 ID로 정리합니다.
- 완료된 TODO 항목은 삭제하며 완료 상태 문서를 추가하지 않습니다.
- 미검증 런타임과 외부 부작용은 완료 보고에서 별도로 밝힙니다.

`git push`, npm 배포, 사용자 전역 설정 변경, 기존 세션 조작은 이 루프가 승인하지
않습니다.
