# Global Dock — PC 선택과 직접 SSH 연결

- 상태: 채택
- 날짜: 2026-11-03
- 근거: 사용자가 제안한 `Global Dock → PC별 Dock → 세션` 구조를 설계·구현하도록 요청했습니다.

## 화면과 이동

2026-11-06 사용자의 후속 결정으로 `waga`의 기본 진입은 전체 PC 통합 Dock입니다.
`Tab`은 전체 PC → 현재 PC → 등록·발견 순서의 원격 PC → 전체 PC로 순환합니다.
`Shift+Tab`은 전체 제공자 → Codex → Claude → 전체 제공자로 독립 순환합니다.
입력·설정 모달과 provider 네이티브 TUI의 Tab 동작은 바꾸지 않습니다.
전체 모드는 연결된 PC·프로젝트·세션 순으로 묶으며, 같은 cwd·native ID도 PC가 다르면 별도 행입니다.
세션이 없는 폴더와 미연결 PC는 기본 목록·탭에서 숨깁니다. `Alt+P`는 모든 발견 PC가 있는
연결 설정 화면을 엽니다. 조회 실패·오프라인 PC의 오류와 이전 자료도 이 화면에 남습니다.
선택·접힘·미리보기 위치는 호스트를 함께 식별하되 native `session.id`는 바꾸지 않습니다.
현재 PC를 먼저, 원격 PC를 등록 순서대로 표시합니다.
기본 보기는 기존 PC·프로젝트 트리입니다. 일반 Dock의 `Alt+V`는 트리/상태 보기를 전환하며
헤더에서 활성 보기와 단축키를 표시합니다. 네이티브 TUI·검색·입력·설정·이름 변경·연결 모달에서는
전환하지 않습니다. PC와 제공자 필터는 두 보기에서 독립적으로 유지합니다.
상태 보기는 보이는 세션을 needs-input → error → working → idle → done → unavailable/unknown
순서로 묶고 빈 그룹을 숨깁니다. idle에서 완료를 추론하지 않습니다. 그룹 안에서는 기존
PC·프로젝트·수동 순서를 유지하며 최근 활동이나 다른 상태로 재정렬하지 않습니다.
트리 없이 상태 기호·짧은 canonical ID·제공자·이름과 별도 PC / 프로젝트 열을 표시하고,
좁은 화면에서는 선택한 세션의 문맥을 목록 아래에 표시합니다. 전체 선택 ID도 유지합니다.
선택은 호스트와 세션 ID로 유지하고 접힘은 상태 목록에 적용하지 않습니다. 트리로 돌아갈 때는
선택한 세션의 부모만 필요에 따라 펼칩니다. 상태 제목은 접속 대상이 아니며 상태 보기의
Shift+↑↓는 폴더 순서를 저장하지 않습니다. 접속·재접속·생성·이름 변경·보관과 미리보기는
기존 호스트 소유권과 작업 경로를 사용하는 동작을 재사용합니다.

보이는 작업 중 세션의 아이콘만 120ms 간격으로 그립니다. 상태가 달라진 행의 이름과
기호는 1초간 강조하고, 하단 안내 줄에는 마지막으로 감지한 변경 한 건의 PC·폴더·이름과
이전/현재 상태·감지 후 경과 시간을 표시합니다. 오류·작업 안내 줄은 유지합니다.
애니메이션은 이전 프레임과 다른 행만 덮어쓰며 화면 전체를 먼저 지우지 않습니다.
화면 전환·리사이즈·native 복귀는 전체를 덮어쓴 뒤 남은 셀을 지웁니다.
각 출력은 synchronized output(DEC 2026)으로 묶으며 사용자 터미널 설정은 변경하지 않습니다.
최초 발견·필터 전환을 변경으로 취급하지 않으며 호스트와 전체 세션 ID로 추적합니다.
애니메이션은 provider 조회·미리보기 조회를 추가하지 않습니다. 숨긴 Dock은 기존 가시성
검사 결과에 따라 그리기를 멈추고, 입력·설정·이름 변경·PC 연결 화면과 네이티브 TUI에서도
고속 그리기를 멈춥니다. 기존 선택·수동 순서·조회 간격과 대화 기록은 변경하지 않습니다.

트리와 각 상태 그룹 안에서는 상태·응답·최근 활동으로 순서를 재정렬하지 않으며,
선택은 변경 가능한 이름 대신 등록 ID로 유지합니다.

`PC 연결 설정`에서 PC 이름·ID, Waga 조회 상태, 프로젝트·세션·작업 중 개수를 표시합니다.
선택한 PC의 프로젝트별 경로와 세션 수를 아래에서 확인합니다. `/` 검색은 PC 이름과 ID에
적용하며 기존 Dock의 세션 검색과 분리합니다. 좁은 화면은 같은 내용을 줄여 표시합니다.
조회 실패를 오프라인이나 세션 0개로 바꾸지 않습니다. 같은 Dock 실행 중 마지막 성공
자료는 확인 시각·오류와 함께 이전 자료로 표시합니다. provider 일부 실패는 일부 조회 실패입니다.
연결된 PC의 Enter는 원격 관리 Dock을 열지 않고 시작 PC의 통합 Dock에서 해당 PC 탭을
선택합니다. 현재 PC도 같은 경로를 사용하며, 이후 Tab은 전체·PC별 탭을 계속 순환합니다.
Tab과 PC 선택 Enter는 PC별 세션 선택·미리보기 위치를 공유하고 제공자·보기 모드는 유지합니다.
조회할 수 없는 등록 PC는 연결 설정에 남겨 오류를 안내합니다. 새 PC의 계정 확인·등록 뒤에도
같은 탭 전환을 사용합니다. 세션 Enter/F4와 생성·관리 동작에서만 원격 터미널에 접속합니다.

현재 PC로 돌아오면 마지막 세션 선택과 프로젝트 접힘·검색·미리보기 스크롤을 유지합니다.
원격 세션의 Enter/F4는 호스트와 정확한 native ID를 함께 전달해 해당 PC에서 접속합니다.
`Alt+G`는 시작 PC의 통합 Dock 선택 위치로 바로 돌아옵니다.
원격 `Alt+D`/`Alt+N`은 생성 모드·provider·선택한 원격 작업 폴더를 전달해 해당 PC의
프롬프트 입력창을 바로 엽니다. PC 제목은 상대 PC의 기본 폴더를 사용합니다. 생성은 상대
PC의 설정·폴더 선택·라우터·provider 경계를 재사용하고 로컬 bridge를 호출하지 않습니다.
새 생성 요청은 관리 view만 다시 열며 retained 네이티브 프로세스는 보존합니다.
처음 연 생성 입력창의 Esc는 그 view를 닫고 시작 PC의 통합 Dock으로 복귀합니다.
원격 관리 Dock은 이름 변경·보관·순서 변경 키로 엽니다.
원격 세션의 F2는 정확한 세션 ID와 현재 트리/상태 보기를 전달해 그 PC의 이름 입력창을
즉시 엽니다. 이전 관리 화면은 편집 요청을 무시하지 않도록 새 관리 view로 교체하며
native TUI는 유지합니다. 저장한 예전 선택·검색·접힘보다 요청한 대상을 우선하고,
취소·저장·갱신 뒤에는 입력창을 자동으로 다시 열지 않습니다. 해당 기능을 지원하지 않는
원격 Waga에는 업데이트 안내를 표시합니다.
원격 관리에도 같은 PC 탭 형식을 표시하고 제목에 원격 관리를 명시합니다. 편집 중이 아닐 때
Tab은 통합 Dock으로 돌아가며 Shift+Tab은 제공자 필터로 유지합니다.
원격 관리 화면의 `Alt+P`도 시작 PC의 Dock으로 복귀합니다. 다른 PC로의 대화형 접속은
처음 실행한 Dock에서만 허용하며, 원격 관리 view의 SSH 창 생성은 거부합니다.
각 PC에서 직접 시작한 Dock의 양방향 접속과 생성 입력창의 `Alt+P` 폴더 선택은 유지합니다.
원격 대화 미리보기는 통합 목록에서 조회하지 않고 네이티브 TUI로 연결해 확인합니다.
원격 관리 Dock의 탐색 위치는 해당 PC의 XDG state 아래
`wattari-gattari/remote-docks/<등록 ID>.json`에 저장합니다. provider 대화 기록은 복제하지 않습니다.

## PC 등록과 연결

설정은 `$XDG_CONFIG_HOME/wattari-gattari/hosts.json` 또는 절대 경로 `--hosts`를 사용합니다.
2026-11-06 사용자의 자동 등록 요청에 따라 PC 목록에서 `tailscale status --json`으로 PC를
자동 발견합니다. 기존 등록을 우선하며 새 PC는 뒤에 추가하고 휴대전화는 제외합니다.
기기의 고정 Tailscale ID를 저장해 이름 변경과 조회 순서 변화가 중복 PC를 만들지 않게 합니다.
OpenSSH 별칭은 설정 문법을 직접 파싱하지 않고 `ssh -G`의 최종 hostname으로 대조합니다.
[예시](../../integrations/hosts.example.json)의 version 1 형식을 사용합니다.
`local`과 최대 16개의 `hosts`에 고정 ID와 표시 이름을 등록합니다. 각 원격 항목은
기존 SSH 설정의 별칭 또는 `사용자@호스트`인 `ssh`와 비대화형 SSH에서도 실행 가능한
Waga 실행파일 `command`를 지정합니다.
실행파일은 이름 또는 절대 경로이며 셸 명령 문자열이 아닙니다.
선택적인 `type`은 `pc`·`wsl`·`vm`이며 종류 배지와 색상에 사용합니다. 생략하면 PC로
표시합니다. 선택한 PC는 배경색으로, 연결·경고·조회 실패는 별도의 상태 색과 문자로 구분합니다.

새 PC는 자동 발견만 하고 접속하지 않습니다. 사용자가 `Alt+P`에서 PC를 선택해 계정명을 입력하면
SSH와 공개 `host-status --json`을 확인하고 성공한 연결만 잠금·원자적 저장으로 등록한 뒤 해당 PC 탭을 선택합니다.
저장된 접속은 자동 조회하며 실패한 PC는 연결 설정에서 다시 열 수 있습니다. 탐색은 PC 목록이 보일
때와 통합 Dock이 보일 때 30초마다 수행하며 탐색 실패가 기존 등록 PC의 조회를 막지 않습니다.
Tailscale SSH의 공개 호스트 키가 있는 기기는 공식 `tailscale ssh`로 접속합니다. 그 외에는
기존 SSH 인증과 호스트 키 검증을 사용하며 암호·최초 키 수락·호스트 키 갱신·SSH 서버 활성화를
자동으로 하지 않습니다. WSL과 Windows는 별도 기기로 표시합니다. 검증되지 않은 후보에는
메시지나 업데이트를 보내지 않습니다. 명시적 등록 파일도 검증된 새 연결의 저장 대상으로 사용합니다.

원격 목록은 공개 `waga list --json`을 비대화형 SSH로 독립 조회합니다. 목록 조회는
Codex daemon을 시작하지 않습니다. 연결 5초·전체 10초·출력 1MiB의 한도를 두고,
한 PC가 지연되어도 다른 PC의 결과를 먼저 표시합니다. 같은 갱신을 중복 실행하지 않으며
통합 Dock과 PC 연결 설정이 숨겨져 있으면 자동 원격 조회를 하지 않습니다.

## TUI와 메시지의 소유권

로컬 tmux backend는 원격 호스트와 선택한 native ID 조합으로 SSH 창을 재사용합니다. 관리 Dock은
호스트별 별도 창으로 재사용합니다. 해당 창에서 `ssh -tt`로
원격 PC의 기존 Waga를 실행하므로 원격 세션 ID를 로컬 native launcher나 archive에 전달하지 않습니다.
로컬 direct backend는 SSH에 터미널을 넘기고 종료 후 목록을 복원합니다.
원격 PC에는 Waga와 tmux가 필요하며 전역 설정이나 daemon을 배포·변경하지 않습니다.

원격 Waga 격리 tmux의 Codex pane은 frontend를 시작하기 전에 기본 전경 `#c0caf5`와
배경 `#1a1b26`을 명시합니다. Codex 0.166.0은 OSC 10/11 조회 실패를 캐시하고 입력창 배경을
생략하므로, 중첩 SSH terminal이 팔레트를 보고하기 전에도 tmux가 두 색을 응답하게 합니다.
첫 입력 화면을 확인하면 임시 pane 스타일을 해제합니다. Codex가 기억한 색상으로 입력줄의
밝은 배경을 유지하고, 답변 영역은 terminal의 기본 반투명 배경으로 돌아갑니다. 로컬 Codex,
Claude, 기존 사용자 tmux server와 전역 테마는 바꾸지 않습니다. 이미 열린 frontend는
같은 대화 ID로 화면을 다시 연결해야 새 색상을 읽습니다.

원격 Codex는 공개 `--no-alt-screen` 옵션으로 실행하여 이전 대화를 tmux scrollback에
남깁니다. 마우스 휠은 바깥 SSH 창에서 원격 tmux로 전달하고, Codex가 마우스를 처리하지
않을 때 원격 tmux의 copy-mode로 이전 대화를 봅니다. 로컬 Codex의 화면 모드와 사용자
전역 설정은 유지합니다.
Waga 전용 격리 tmux 서버는 `set-clipboard on`으로 원격 copy-mode의 OSC 52 복사를
로컬 터미널까지 전달하고 `hyperlinks` 기능으로 OSC 8 링크를 보존합니다. 기존 사용자
tmux 서버의 정책은 변경하지 않습니다. 실제 OS 클립보드와 브라우저 열기는 로컬 터미널이
처리합니다. WezTerm에서 마우스 보고 중에도 로컬 링크를 열려면 Ctrl+클릭의 Down/Up을
함께 바인딩해야 하며, 일반 클릭·드래그·휠은 tmux로 전달합니다. Waga가 사용자 터미널의
설정을 자동 설치하지는 않습니다.
원격 재연결은 `-c check_for_update_on_startup=false`로 실행해 provider 업데이트 안내가
접속 준비를 막지 않게 합니다. provider 설치나 전역 업데이트 설정은 변경하지 않습니다.

중첩 tmux에서 `Alt+G`는 시작 PC의 Dock으로 복귀하고 `Alt+A`는 원격으로 전달합니다. 실패한 연결은 오류를
읽을 수 있도록 남기며 `Alt+G`로 원래 목록에 돌아옵니다. 원격 PC 이름은 Dock과 tmux 상태 줄에 표시합니다.
원격 tmux client는 `ignore-size`로 연결하여 다른 로컬 client의 화면 크기에 영향을 주지 않습니다.
로컬 client가 없는 경우에는 기존 tmux 크기 규칙을 따릅니다. 동시 입력은 기존 tmux 공유
동작을 따르며 별도 입력 소유권 잠금이나 읽기 전용 관찰 모드는 이 변경에 추가하지 않습니다.

연결 해제는 SSH와 해당 view만 정리합니다. retained native 프로세스와 작업은 원래 PC에 남습니다.
PC 전원 종료나 네이티브 프로세스 자체의 종료를 tmux가 복구하는 것으로 취급하지 않습니다.

`list/send/ask/result --host <등록 ID>`는 상대 PC의 기존 CLI를 호출합니다. cwd는
상대 PC의 경로로 해석합니다. 메시지와 인자를 기존 셸 인용 함수로 전달하며 실행할 셸 코드로
취급하지 않습니다. stdout·종료 코드·요청 ID·접수 상태를 그대로 돌려줍니다.
`local-queued`는 상대 PC Waga의 저장 확인이며 네이티브 수신이나 답변이 아닙니다.
결과는 같은 PC의 `result --host`로 조회합니다. 로컬 Claude 소켓을 사용하는
`--notify-origin`은 원격에서 사용할 수 없습니다.

SSH가 끊겨 접수를 확인할 수 없는 메시지는 자동 재전송하지 않습니다. 요청 ID를 받았다면
원래 요청을 조회하고, ID도 받지 못했다면 상대 PC 기록을 확인해야 합니다.
peer 메시지의 불신 입력 경계와 provider별 요청·응답 연결은 기존 메시징 계약을 유지합니다.

## Oracle 중계와 검증 경계

이 단계는 PC 선택과 직접 연결입니다. Oracle의 상시 디렉터리·오프라인 접수·중계,
전역 메시지 중복 방지와 입력 소유권 정책은 후속 설계입니다. 로컬 HTTP 서버를 네트워크에
노출하거나 provider 소켓을 공유하는 방식으로 대체하지 않습니다.

동작 검사는 설정·부분 실패·안정된 순서·선택 복원·메시지 인용과 함께,
폐기용 SSH 서버 및 두 tmux 서버를 연결하여 중첩 단축키·입력·복귀·크기·연결 해제를 확인합니다.
이때 provider는 제어 가능한 프로세스 fixture입니다. 실제 PC 간 Claude·Codex 전달과
Oracle 운영 증거는 이 검사와 구분합니다.

## 원격 업데이트

Alt+P의 `u`는 선택한 원격 PC만 갱신하며 현재 PC에서 누르면 로컬과 등록 PC 전체를 갱신합니다.
`U`는 어느 행에서도 로컬과 등록 PC 전체를 갱신합니다. CLI의 `waga update`와 `--all`도 같은 기본값이고,
`--host <ID>`는 지정한 원격 PC만 갱신합니다. 기존 `--hosts`는 등록 파일을 지정합니다.
`--source /absolute/checkout`은 새로 배포할 저장소를 명시합니다. 생략하면 프로젝트 GitHub
저장소의 최신 `main`을 임시 checkout으로 가져옵니다. 시작 PC의 설치본을 재배포하지 않으며,
Git이나 네트워크 오류로 최신 조회에 실패하면 이전 설치본으로 대체하지 않고 배포를 중단합니다.
로컬 작업 폴더는 커밋된 깨끗한 Waga checkout이어야 하며, 설치본에서 실행하면 현재 활성
release와 별개로 준비한 같은 소스 묶음을 전달합니다. 등록 PC를 순차 처리하고 한 PC의 실패는
다른 PC의 설치를 취소하지 않습니다. 메시지나 provider 업데이트 명령을 함께 실행하지 않습니다.
로컬 설치가 실패하면 원격 배포를 시작하지 않으며 로컬·원격은 한 번 준비한 동일 묶음을 사용합니다.
주기적 배포·PC 간 버전의 자동 전파는 하지 않습니다. 실패한 PC는 같은 명령으로 재시도합니다.

소스 묶음에는 `git rev-list`의 커밋 이력을 `git archive --add-file`로 함께 담습니다.
shallow checkout은 이력 증명이 불완전하므로 거부합니다. 설치 잠금 안에서 현재 커밋이 후보의
이력에 포함되는지 확인하고 구버전·갈라진 브랜치·이력 누락은 current 변경 전에 거부합니다.
동일 커밋은 기존 archive hash 확인 후 그대로 유지합니다. 수정된 SSH 배포는 수신 PC에
보호 기능이 있는 설치기가 있으면 그 설치기를 사용해 오래된 후보의 설치기로 우회하지 않습니다.
수정 전 송신 프로그램은 이 절차를 사용하지 않으므로 등록 PC마다 수정본을 한 번 설치해야 합니다.

기존 SSH 인증을 사용해 Git archive와 SHA-256을 전달합니다. 상대 PC의 선택적 `node`
설정은 비대화형 SSH에서 실행할 Node 이름 또는 절대 경로입니다. 생략하면 `node`이며,
Node가 NVM 등으로 설치돼 SSH PATH에 없다면 한 번 등록합니다. 설치는 사용자 앱 폴더의
`releases/<commit>`에서 `npm ci`로 수행하며 PC 간 node_modules를 복사하지 않습니다.
의존성 설치에는 해당 PC의 npm registry 접근 또는 캐시가 필요합니다.

설치기는 기존 flock 파일 잠금으로 직렬화합니다. 검증한 파일과 실행파일·런타임 의존성을
준비한 뒤 `current` 링크를 원자적으로 전환하며, 기동 확인 실패는 이전 링크로 복구합니다.
고정 실행 경로는 `~/.local/share/wattari-gattari/waga`입니다. 성공한 PC의 등록 경로만
잠금과 원자적 저장으로 갱신하며 동시 등록 변경은 거부합니다. 전송 결과가 불명확하면
같은 버전의 재실행으로 설치 상태를 확인할 수 있으며, 이미 활성인 같은 버전은 재설치하지 않습니다.
이전 release와 실행 중인 native host·메시지 worker는 삭제하거나 강제 종료하지 않습니다.
설치기는 `~/.local/bin/waga`를 고정 실행 경로에 연결하며 다른 실행파일은 덮어쓰지 않습니다.
npm link의 공개 `waga` 진입점도 관리 설치본을 우선하고, 개발 저장소 직접 실행은
`node src/cli.mjs`로 구분합니다. 셸 PATH나 provider 전역 설정은 변경하지 않습니다.

설치된 버전과 같은 Waga tmux 서버의 Dock 실행 버전을 따로 표시합니다. 관리 설치본의
Dock은 새 버전을 발견하면 자신의 overview PID·활성 창·표시 client를 확인한 뒤 그 pane만
다시 실행합니다. 네이티브 TUI가 표시 중이거나 입력·검색·설정 편집 중이면 복귀/편집 종료까지
미룹니다. 원격 탐색 저장을 이용해 선택·필터·접힘·스크롤을 복구하고 tmux 설정도 새 코드로
갱신합니다. CLI/provider 자체의 실행 중인 코드를 교체하는 기능은 아닙니다.

이 기능이 없는 기존 설치본은 최초 업데이트 후 원격 Dock을 한 번 다시 열어야 합니다.
이후 관리 설치본끼리의 업데이트는 위 자동 적용을 사용합니다. 구버전 목록 조회는 기존
`list --json`으로 호환하고, 새 `host-status --json`은 provider 조회 실패와 설치 상태를
분리하므로 Claude·Codex가 없는 PC의 설치를 실패로 취급하지 않습니다.

일부 구버전 tmux/libutempter에서는 PTY 종료 중 SIGCHLD를 놓쳐 종료된 SSH가 회수되지
않습니다([상위 결함과 수정](https://github.com/tmux/tmux/issues/4559)). Waga 전용 격리
서버에서 소유한 원격 창의 pane은 종료됐지만 종료 코드·신호가 모두 미확인인 경우에만
서버에 SIGCHLD를 알립니다. 서버 재시작이나 프로세스 중단, 사용자 tmux 설정 변경은 없습니다.
