# Codex·Claude 통합 화면 v0

Claude Agents View의 운용 감각을 유지하되, 자율 통합 에이전트가 아니라 사용자가
Codex와 Claude 작업세션을 직접 제어하는 화면입니다.

## 한 화면의 구성

```text
 Wattari Gattari  codex + claude     global · revision 42
 1 awaiting input · 3 working · 1 approval · 0 completed

> ▾ sample-app  3 sessions · ~/work/sample-app
  X #130 상태확인내역중복조사       Working   마지막 활동 한 줄
  C #40 스냅샷업로드에서fail-open  Needs input  권한 입력 대기
  X #126 데이터베이스마이그레이션  Working   테스트 실행 중

 > describe a task for a new session
 empty enter/→: open · type+enter: new · F2: rename · ctrl+x: stop
```

- 머리글은 제공자, 전역 revision, 프로젝트와 상태별 세션 수를 보여줍니다.
- 세션 한 개는 이름, 상태, 마지막 활동 한 줄만 차지합니다.
- 프로젝트가 여러 개면 프로젝트 경로별로 묶고, 세션이 없는 프로젝트도 행을 유지합니다.
- 아래 입력줄은 새 작업세션의 최초 프롬프트를 받습니다.
- 입력줄은 터미널 폭 구분선으로 transcript와 분리하고, 실제 입력 위치에 깜빡이는
  막대 커서를 표시합니다. 승인·종료 확인처럼 텍스트를 받지 않는 동안에는 커서를
  숨깁니다.
- 기본 화면에는 긴 transcript나 에이전트 간 대화를 펼치지 않습니다.

## 화면 전환과 커서

통합 TUI는 `목록 모드`와 `세션 대화 모드`를 같은 터미널 안에서 전환합니다.

- 목록의 커서는 `↑`/`↓`로 프로젝트와 세션 행을 함께 순회합니다. 프로젝트 행에서
  `Enter`는 로컬 화면에서만 접기/펼치기를 바꿉니다.
- 입력줄이 비어 있을 때 `Enter` 또는 `→`를 누르면 선택한 세션의 대화 모드로
  들어갑니다.
- 세션 대화 모드에서 `←`를 누르면 세션을 중단하지 않고 목록으로 돌아옵니다.
- 세션 대화 모드의 입력창은 터미널 하단에 맞추고, 윗 구분선 오른쪽에 현재 세션
  이름을 표시합니다. 사용자 입력은 배경색 행, 에이전트 출력은 이름 접두사 대신
  작은 점(`•`)으로 구분합니다.
- 입력창 바로 위에는 작업 중일 때만 `Working` 경과 시간과 `Esc interrupt`를
  표시합니다. 상시 도움말은 표시하지 않습니다. 입력창 아래 상태선은 확보된 실제
  값으로 작업 경로, Git branch, 모델·추론 강도, 현재 토큰/context 한도와 계정 한도를
  표시합니다. 실제 토큰 값이 아직 없으면 현재 화면에 로드된 대화문만 계산한 추정치를
  `tokens ~… visible`로 명시해 표시합니다.
- 글꼴은 터미널 설정을 그대로 사용하고, 어두운 배경용 내장 true-color 팔레트가
  Codex·Claude accent, 사용자 입력 배경, 상태 정보를 의미별로 구분합니다.
- 세션 대화 모드에서 `↑`/`↓`를 누르면 해당 세션의 이전 사용자 입력을 최신순으로
  순회하며, 마지막 입력 다음에는 탐색 전에 작성하던 초안을 복원합니다.
- 세션 대화 모드는 최근 thread item 최대 100개의 대화 메시지를 먼저 표시합니다.
  더 오래된 대화가 있으면 `PageUp`으로 이전 페이지를 명시적으로 불러오며, 불러온 이력은 후속 상태 갱신에도
  유지합니다.
- 목록 입력줄에 텍스트가 있으면 `Enter`는 선택 세션을 여는 대신 새 세션을 만들고
  그 텍스트를 최초 프롬프트로 보냅니다.
- 목록에서 `Tab`은 새 세션 제공자를 Codex와 Claude 사이에서 바꿉니다. 세션에서
  `Space`는 빠른 답장을 열고, `Shift+↑`/`Shift+↓`는 모든 TUI가 공유하는 순서를
  바꿉니다. `F3`은 유휴 세션을 사용자가 명시적으로 `Completed`로 표시하거나 다시
  `Awaiting input`/`Sleeping` 상태로 엽니다. 새 메시지를 보내면 완료 표시는 자동으로 해제됩니다.
- 대화 모드에서 나온 뒤에도 작업은 계속되며 목록 행의 상태와 마지막 활동이
  갱신됩니다.
- Codex 작업 중 입력한 일반 메시지는 `turn/steer`로 현재 턴에 추가합니다. 입력창이
  비어 있을 때 `Esc`를 누르거나 `/interrupt`를 실행하면 현재 턴만 중단하고 세션과
  transcript는 유지합니다. Claude 작업 중 추가 메시지는 세션 복제를 막기 위해
  거절하지만 `Esc` 중단은 지원합니다.
- `/` 메뉴는 `/status`, `/statusline`, `/interrupt`, `/rename`, `/back`, `/help`를
  로컬에서 처리합니다. 알려지지 않은 slash 시작 텍스트는 일반 프롬프트로 전달합니다.

상세 진입은 선택된 thread를 다시 전체 목록에서 찾지 않고 바로 최근 transcript를
조회합니다. 화면에는 터미널 높이에 맞는 메시지만 그리며, 터미널 `resize` 이벤트마다
새 열 너비로 transcript와 입력 내용을 다시 줄바꿈하고 세션명·하단 구분선을 포함한
입력 영역 전체를 재배치합니다. 자동 갱신 캐시는 최근 100항목 페이지로 제한하고, 화면이 쓰지 않는 App Server
delta 알림은 초기화 단계에서 받지 않습니다. 알림이 몰릴 때는 짧게 합쳐서 한 번만
새로고침하고 동일한 terminal frame은 다시 출력하지 않습니다.

따라서 운영체제 창이나 별도 터미널 pane을 선택하는 방식이 아니라, 통합 TUI가
세션 목록과 각 세션 대화를 직접 소유하는 방식입니다.

여기서 "소유"는 화면 프로세스가 작업 프로세스의 부모라는 뜻이 아닙니다. 실제
세션과 진행 중인 턴은 백그라운드 서비스가 소유하고, TUI는 그 서비스에 붙는
관제 클라이언트입니다. TUI를 종료했다가 다시 실행해도 같은 세션 카탈로그와
transcript를 다시 보여줘야 하며, 화면 종료는 세션 stop으로 취급하지 않습니다.

## 세션 동작

- **새 세션**: 사용자가 제공자와 프로젝트를 선택하고 최초 프롬프트를 입력합니다.
  예: `/issue-loop #127번 이슈 확인하고 처리해줘`.
- **열기/전환**: 선택한 세션의 대화와 현재 작업을 같은 통합 TUI 안에서 봅니다.
- **이름 변경**: 표시 이름만 바꾸며 thread/session 식별자는 유지합니다.
- **종료**: 선택한 세션의 진행 중인 턴과 관리 프로세스를 끝냅니다. 실행 중인
  세션은 영향을 명시하고, `Ctrl+X`를 한 번 더 눌러야만 종료합니다. 확인 중 다른
  키는 모두 취소로 처리합니다. 종료한 세션은 통합 목록과 관리 카탈로그에서
  사라지지만 Codex 원본 transcript는 삭제하지 않습니다.
- **전체 종료**: 단축키 한 번으로 바로 실행하지 않고 대상 수를 보여준 뒤 명시적으로
  확인받습니다.
- **화면 종료**: 백그라운드 세션에는 영향을 주지 않고 화면 연결만 끊습니다.
- **서비스 종료**: `Ctrl+Q`를 누르고 확인창에서 `Ctrl+Q`를 한 번 더 눌러 TUI와
  waga 백그라운드 App Server를 함께 종료합니다. 확인 중 다른 키는 모두
  취소입니다. 진행 중인 턴은 끊길 수 있지만 thread, transcript, 세션 카탈로그는
  삭제하지 않으며 다음 TUI 실행에서 서비스를 새 코드로 다시 띄웁니다.

작업세션을 종료하는 것, transcript를 삭제하는 것, worktree를 정리하는 것은 서로
다른 동작입니다. v0의 `stop`은 앞의 것만 담당합니다.

## 상태

| 상태 | 의미 |
|---|---|
| `Awaiting input` | 이전 턴이 끝났고 사용자 지시를 기다림 |
| `Working` | 모델 턴 또는 도구 실행이 진행 중 |
| `Approval` | 중요 작업이 직접 사용자 승인을 기다림 |
| `Needs input` | Claude 고유 권한/질문 입력이 필요함. `claude attach <id>`에서 처리 |
| `Completed` | 맡은 작업을 보고하고 멈춤 |
| `Sleeping` | 세션 기록은 남아 있지만 유휴 상태라 현재 버스 라우팅 대상이 아님 |
| `Stopped` | 사용자가 세션 실행을 종료함 |
| `Error` | 제공자 연결, 턴, 도구 실행이 실패함 |

`issue-loop`의 “한 이슈를 완주하고 멈춤”은 사용자가 보고를 확인한 뒤 `F3`으로
`Completed` 표시합니다. provider의 단순한 턴 종료는 작업 완료와 구별할 수 없으므로
자동 완료로 추론하지 않습니다. 완료된 세션이 새 이슈를 스스로 고르거나 다른 세션을
만들지는 않습니다.

통합 화면의 **세션 카탈로그**와 에이전트 간 통신의 **라우팅 대상 목록**은 서로
다릅니다. `Sleeping` 세션은 통합 화면 목록에는 계속 보이지만 `list_agents()`에는
나오지 않습니다. 사용자가 해당 행에 들어가 기존 thread를 resume하면 다시 통신
가능 상태로 등록됩니다. `←`로 상세 화면을 나오는 동작만으로 즉시 sleep시키지는
않으며, sleep은 별도의 유휴 정책이 결정합니다.

## 승인 화면

승인은 상태 행에 `Approval`로 표시하고, 상세 보기에서 다음을 보여줍니다.

- 요청 세션과 제공자
- 실행할 명령 또는 변경할 대상
- workspace 내부/외부와 외부 시스템 영향
- 승인 이유와 적용 범위

승인/거부는 포그라운드 TUI의 직접 키 입력으로만 App Server의 대기 중인 요청을
해결합니다. waga 소켓, 작업세션 메시지, 다른 LLM의 답변에는 승인 API를
노출하지 않습니다. 연결 종료와 시간 만료는 거부로 처리합니다.

`y`는 훅의 session·turn·tool item 식별자와 명령 원문을 15초 동안만 보관합니다.
이어지는 App Server 승인 요청이 같은 식별자와 명령을 모두 제시할 때 한 번만
허용하고 즉시 폐기합니다. 같은 item의 명령이 바뀌거나 재사용되거나 만료되면
거부합니다. 현재 App Server 요청과 안전하게 대응시킬 수 없는 권한확대 요청도
fail-closed로 거부합니다.

구현된 v0는 App Server 훅과 별도의 사용자 전용 Unix 소켓을 사용합니다. 훅은
요청 원문을 보내고, 포그라운드 화면은 같은 원문을 독립적으로 다시 분류한 뒤에만
관리 카탈로그에 있는 thread인지 확인하고 `y` 또는 `n`을 받습니다. 승인 요청은
FIFO로 대기하고 화면에는 현재 하나만 표시됩니다. 화면이 없거나 소켓 응답이 잘못되면 fail-closed로
차단합니다. 현재 분류기는 삭제, Git push와
강제 초기화, 서비스·프로세스 중단, 배포, 권한 확대와 실행 중 프로세스 입력을
다루는 v0 규칙이며 임의 스크립트의 모든 파괴 효과를 완전 판별하는 경계는 아닙니다.

화면은 정확한 세션 플래그 훅이 발견된 경우에만 workspace-write를 켭니다. 기존
백그라운드가 훅 없이 실행 중이면 헤더에 `read-only compatibility`를 표시하고
쓰기 권한을 올리지 않습니다.

## 구현 순서

1. 완료: 메모리 전용 프로토타입으로 커서, 목록↔대화 전환, 새 세션, 이름 변경,
   종료 확인의 조작감을 검증
2. 완료: Codex 관리 세션 하나의 생성, 상태 갱신, 이름 변경, 명시적 종료와 화면
   재접속. 화면을 두 번 실행해 같은 실제 thread와 transcript가 보이는 것을 검증
3. 완료: 일반 workspace 작업 자동 실행, 중요 작업 승인
   대기/거부, 화면 부재 시 실제 삭제 차단, 직접 입력과 App Server 요청의 일회성
   상관관계 연결. 사용자가 직접 `y`를 누른 뒤 표식 파일 삭제와 부재 확인까지 검증
4. 완료: Codex 여러 세션의 독립 생성, 목록, 전환, 순서 변경, 종료
5. 완료: Claude 공식 background CLI와 agents JSON을 같은 세션 행·상태 모델에 연결
6. 완료: 전역 daemon, 여러 TUI의 즉시 상태 broadcast, 프로젝트 행·빈 프로젝트 보존
7. 완료: Codex/Claude ephemeral shadow를 통한 한 요청·한 응답 peer 통신
8. 완료: 전역 `waga` CLI, 진단·중단·peer 명령과 npm 패키지 구성

v0의 socket과 PID는 `$XDG_RUNTIME_DIR/wattari-gattari`, 관리 카탈로그와 로그는
`$XDG_STATE_HOME/wattari-gattari` 또는 `~/.local/state/wattari-gattari`에 저장합니다.
이전 `agent-bus` 상태 파일은 최초 실행에서 복사하고 원본은 보존합니다.
Codex 0.152.0은 `thread/start` 응답과 transcript에는 `threadSource`를 남기지만 이후
`thread/list`에서는 이를 `null`로 반환하므로, 통합 화면이 만든 thread ID만 별도
기록하고 Codex가 반환한 최신 상태·메시지와 결합합니다.
