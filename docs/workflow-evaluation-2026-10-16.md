# 작업 실행 실측 — 2026-10-16

목적은 작은 실제 Waga 수정 과제에서 검사·독립 검토·회수 경계를 확인하는 것입니다.
프로젝트 전체 품질이나 일반적인 모델 순위를 입증하는 벤치마크가 아닙니다.

## 과제와 확인 근거

구현 중 발견한 두 결함을 현재 Waga 모듈의 격리 복사본에서 수정했습니다.

- `work-context.mjs`: 유한수이지만 JavaScript Date 범위를 벗어난 관측 시각을 허용해
  인계 생성 시 예외가 발생하는 문제. 유효한 시각 보존과 범위 밖 시각 거부를 검사했습니다.
- `workflow-provider.mjs`: 사유가 없거나 문자열이 아닌 Codex 검토 결과의 `pass`를
  인정하는 문제. 정상 결과·native identity·usage 보존과 잘못된 통과 거부를 검사했습니다.

검사 파일은 작성 에이전트가 수정할 수 없는 선언 범위에 두었습니다. 실제 Node 검사 뒤
별도 native 세션이 구현·검사 파일을 읽었습니다. 검토자는 검사를 직접 재실행하지 않았으며,
기계 검사의 종료 코드와 읽기 검토의 판정을 따로 기록했습니다. 실행기는 원본에 자동 적용하지 않았고,
확인한 작은 수정만 개발 checkout에 반영한 뒤 회귀 테스트에 포함했습니다.

| 구성 | 실제 결과 | 시간 | 보고된 비용 | 관측 여유 메모리 최저 | 관측 CPU 최대 |
|---|---|---:|---:|---:|---:|
| Claude Haiku, 두 과제 순차 | 두 과제 각각 1회 검사·별도 검토 통과 | 39.9초 | $0.00805842 | 21.0GiB | 25.0% |
| 같은 두 과제·모델, 최대 2개 병렬 | 두 과제 각각 1회 검사·별도 검토 통과 | 23.3초 | $0.00642826 | 20.6GiB | 17.6% |
| Codex GPT-6.1-Sol, 제공자 결과 파서 한 과제 | 1회 검사·별도 Codex 검토 통과 | 45.9초 | 미제공 | 19.9GiB | 35.0% |

같은 두 Claude 과제의 이 실행에서는 병렬 쪽이 빨랐습니다. 실행 순서·서버 캐시·호스트의
다른 작업·작은 표본 때문에 시간과 비용 차이를 일반화하지 않습니다. 기본 순차 실행을
유지하고 파일 충돌이 없는 작업에만 두 개까지 명시적으로 허용하는 구성을 유지합니다.
사용자 재지시나 최종 확인 클릭을 과제 완료로 계산하지 않았습니다. 완료 상태는 모두
`review_required`로 남았으며 원본 적용·머지·배포는 실행하지 않았습니다.

Claude의 reported input/cache creation/cache read/output을 별도 보존합니다. Codex 성공
실행은 작업자 input 63,607/output 583, 검토자 input 62,629/output 296을 보고했습니다.
그중 cached input은 각각 53,376, 40,448입니다. 이 숫자는 청구액이 아닙니다.

## 실패와 수정

첫 Codex 실행에는 Claude용 “명령 실행 금지”를 그대로 전달했습니다. Codex의 파일 조회까지
막혀 실제 검사가 3회 실패했고 무진전 중단이 동작했습니다. 이 실패를 성공 통계에서
제외한 채 숨기지 않습니다. 실행기는 이를 자동 완료로 처리하지 않았습니다. 구현자가
조회 경계 문구를 수정하는 개입 1회 후, 같은 과제를 웹에서 다시 시작해 위 성공을 확인했습니다.
제공자별 도구 경계가 다르므로 단순히 실행 파일 이름만 교체해서는 안 된다는 근거입니다.

별도 실제 Node 프로세스 실험에서는 조정 실행기를 SIGKILL한 뒤 디스크 결과를 회수해
부작용이 한 번만 발생함을 검사했습니다. 서버가 접수한 뒤 HTTP 응답을 잃는 경우는
실제 로컬 HTTP 서버와 의도적 응답 유실 경계로 검사했고, native 모델은 fixture였습니다.
권한 대기·무진전 중단·검증 후 변경 무효화도 회귀 테스트로 확인했습니다.

웹에서는 실제 Codex 실행 시작·연속 클릭의 중복 방지·검사 결과 열기를 확인했습니다.
세션 간 인계는 fake native 입력 carrier로 목표·원문 출처·자료 버전 보존과 입력 대상
격리를 확인했습니다. 이 UI 검사는 실제 Claude/Codex TUI 입력을 입증하지 않습니다.
기존 사용자 세션·daemon·전역 설정은 조작하지 않았습니다.

비공개 실행 원본과 샘플은 실험 당시 `/tmp/waga-proof-orchestration`에 남겼습니다.
임시 경로의 영구 보존은 보장하지 않습니다. native JSONL 파서 fixture와 동작 회귀는
`test/workflow-recovery.test.mjs`, `test/workflow-runtime.test.mjs`, `test/work-store.test.mjs`에서
다시 실행할 수 있습니다. 실제 모델 호출 비용·속도 재현은 별도의 작은 실측이 필요합니다.

Codex 실행 경계는 [공식 비대화형 실행 문서](https://developers.openai.com/codex/noninteractive)와
설치된 `codex exec --help`를 대조했습니다.

연결했습니다. 사용자가 JSON 명세나 인계 항목을 먼저 작성할 필요가 없습니다.
LLM 제안은 관측된 호출 관계나 검사 통과로 바꾸지 않으며, 실제 호출 ID가 일치하는
경우만 도구 기록으로 연결합니다. 대화의 시간상 인접 관계는 인과관계가 아닙니다.

`/tmp/waga-proof-work-assistant`의 폐기용 git 저장소에서 기존 대화 carrier는 fixture로
제공하고, 정리 모델·격리 수정·검사·독립 리뷰는 실제 native CLI로 실행했습니다.
과제는 `value.mjs`의 내보내는 값을 1에서 2로 바꾸고 기존 `npm test`로 확인하는

  거부됐습니다. 출처 enum과 지시를 보강한 뒤 명시적으로 다시 실행했습니다.

사용자 인계 정정 보존, 오래된 계획·작업 중 세션 실행 거부, 같은 계획의 동시 요청
중복 방지를 포함합니다. 실제 모델 응답 fixture는 두 제공자 모두 보존했습니다.

이는 작은 과제의 동선·제공자 경계 실측입니다. 복잡한 프로젝트의 작업 분해 품질이나
모든 제안의 실행 가능성을 입증하지 않습니다. 분석은 열 때 한 번 실행하고 결과를
재사용합니다. 실패를 몰래 재시도하지 않으며 갱신은 명시적입니다. 원본 git이 깨끗하고
자료 버전이 일치하는 검증된 계획만 별도로 실행합니다.
