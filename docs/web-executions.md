# 웹 실행 기록

웹의 **실행 흐름**은 dock에 보이는 활성 세션의 기록을 자동으로 수집합니다.
세션 선택이나 실행 흐름 탭을 열기 전부터 수집하며, 별도 파일 가져오기 조작은 없습니다.

## 일반 세션 자동 수집

- Claude는 해당 세션의 로컬 JSONL을, Codex는 owning App Server의 `thread/items/list`를
  읽습니다. 세션 입력·resume·제공자 설정 변경이나 모델 호출을 하지 않습니다.
- 서버 시작 및 5초 간격으로 활성 목록을 확인하고 겹치지 않는 한 수집 작업에서 순차 조회합니다.
  최신 기록을 갱신하며 이전 기록은 페이지별로 보충합니다. 큰 목록이나 느린 제공자는 한 회차가
  5초보다 길 수 있습니다. 실패해도 다른 세션은 계속 수집하고 마지막 정상 기록과 오류를 표시합니다.
- Claude `tool_use`·`tool_result` ID와 Codex native item ID로 결과를 연결하고 중복을 제거합니다.
  Claude의 결과에 기록된 agent ID 및 Codex의 명시적 receiver thread ID를 따라 하위 기록도
  순차 수집합니다. 하위 기록이 없거나 접근되지 않으면 관계만 남기고 갱신 오류를 표시합니다.
- 일반 기록은 OTLP span 자체가 아닙니다. 화면용 ID는 native ID에서 안정적으로 파생하며,
  기록에 없는 부모 관계·모델 요청 시간·토큰 수·검증 통과를 만들지 않습니다. 특히 Claude의
  기록 시각을 실제 요청 소요 시간으로 표시하지 않습니다.
- 세션별 최근 2,000개 항목·3MiB 안에서 보관하고, 긴 입력·출력은 각각 4,000자로 제한합니다.
  제한이나 읽지 못한 항목은 표시합니다. 원본 transcript는 수정하지 않습니다.
- 자동 수집 결과는 `$XDG_STATE_HOME/wattari-gattari/executions` (기본 `~/.local/state` 아래)에
  디렉터리 0700·파일 0600으로 저장합니다. 재시작해도 같은 native identity의 파일을 갱신합니다.
  코드와 도구 출력이 포함되며, 웹은 인증 후 해당 세션과 연결된 기록만 텍스트로 표시합니다.

기존 OTLP JSON 가져오기 HTTP API는 호환을 위해 유지합니다. 이미 가져온 기록과
`waga run`의 실시간 OpenTelemetry 기록은 자동 native 기록과 구별해 선택할 수 있습니다.
OTLP 가져오기는 입력·출력 선택 시 각각 16,000자·이벤트 20개 제한을 유지합니다.

## 실행 기록 탐색

실행 흐름은 개별 도구 호출을 시간순으로 표시하며 파일 변경·명령·오류 필터와 파일·명령 검색을 제공합니다.
최근 80개부터 표시하고 이전 기록을 추가로 펼칩니다. 실제 하위 에이전트가 있으면 호출자와 에이전트별 필터를 표시합니다.
변경 파일을 선택하면 마지막으로 기록된 해당 파일 변경을 옆에서 확인하고, 시간순 목록에서는 이전 변경도 선택할 수 있습니다.
목록과 상세는 각각 스크롤하며 갱신 시 선택·검색·읽던 위치를 유지합니다.

Codex의 파일별 diff와 Claude의 교체 전·후 입력을 추가·삭제 색상으로 표시합니다. Claude 입력은
**도구에 전달된 요청**이며, 거부·오류가 난 요청을 적용 완료로 표시하지 않습니다. Write의 기존 파일
내용이 없으면 작성 요청 내용만 표시합니다. 명령 문자열로 패치를 추정하거나 현재 git diff를 과거 수정으로 대체하지 않습니다.
Codex의 여러 파일 변경은 호출당 최대 40개, 각 diff와 Claude 교체 전·후는 각각 4,000자로 제한합니다.
기존 저장 기록도 읽되 잘린 JSON 등으로 본문을 복원할 수 없으면 미기록으로 표시하고 원문 근거를 남깁니다.

## 표시 의미

`traceId`·`parentSpanId`로 확인된 다른 에이전트의 호출만 연결합니다. 내부 execution span을
거슬러 호출자를 찾으며, 없는 부모나 순환을 추측으로 보완하지 않습니다. 시간 순서는 도구 목록의
표시 순서일 뿐 작업 의존성이 아닙니다. 실행 종료를 확인하지 못한 span은 ‘종료 미확인’입니다.

**호출 종료는 검사 통과가 아닙니다.** status unset/OK와 종료 시각만으로 테스트·작업을
통과시키지 않습니다. span 오류는 오류로 표시하지만 명령 내부의 실패는 출력에서 확인해야 합니다.
로컬 실행의 **작업 그래프**는 선언된 입출력 의존성을, **이 작업의 호출**은 관측한 span 부모 관계를 표시합니다.
선택한 작업에서 회차별 검사 종료 코드·출력, 독립 검증 사유, 산출물 SHA-256과 diff를 확인합니다.

## 로컬 워크플로 실행

일반 대화는 질문·답변 그대로 표시합니다. 대화 조회·응답 종료를 이유로 새 작업이나
관계·인계 요약을 만들거나 별도 모델을 호출하지 않습니다. 현재 진행은 기존 세션 상태와
native 도구 항목, 승인은 기존 승인 경로로 표시합니다.

이슈루프 같은 다단계 스킬을 시작한 에이전트가 이미 작성하는 계획을 등록하면,
**실행 흐름**에서 작업 단계·선행 관계·진행 중인 단계·막힌 이유를 확인합니다.
등록만 한 계획의 다음 단계나 변경은 같은 계획의 갱신으로 반영합니다. 단계 종료는 에이전트의
보고이며 동작 검사 통과와 구분합니다. 사용자는 계획 JSON을 작성하지 않습니다.
에이전트용 등록·갱신 형식과 기존 세션 연동 범위는 [작업 계획](work-plans.md)을 따릅니다.

수행 에이전트가 실행 명세를 포함해 `waga plan <세션 ID> <계획 파일> --execute`로
인계하면 같은 그래프를 실행기가 스케줄링합니다. 원래 에이전트는 중복 수정을 멈추고
결과를 회수합니다. 검증된 JSON 산출물의 조건 분기, 제외된 경로의 모델 미호출,
선택 경로 합류와 실패한 작업의 수정 반복을 실행 상태·근거로 표시합니다.
같은 입력을 읽는 독립 작업은 자원 여유와 쓰기 충돌을 확인한 뒤 병렬로 시작합니다.
현재 계획이나 연결된 실행을 기본으로 엽니다. **작업 기록**은 작업별 제목·날짜·결과와
검색을 제공하고, 같은 작업의 과거 실행만 그 안에 접어 표시합니다. **세션 호출 기록**은
작업 기록과 섞지 않고 바로 엽니다. 과거 대화별 LLM 제안은 기본 목록에 넣지 않습니다.
실행 중 조작은 **실행 관리** 안에 두며, 검사·검토가 종료되면 숨깁니다.

웹에서 전달한 지시의 전송 기록은 native 메시지 원문과 연결합니다. 유일한 내용 일치는
탐색용이며 native turn의 전송 확인이 아닙니다. 전달 미확정 지시는 자동 재전송하지 않습니다.
명시적인 계획이나 연결된 실행이 있는 지시에만 짧은 **그래프** 링크와 **지시·컨텍스트**를
표시합니다. 도구 호출만으로 작업 카드를 만들지 않으며, 대화 안에 시도별 실행 로그를
중복 나열하지 않습니다. 컨텍스트의 목표·결정·출처를 저장하고 후속 지시 또는 다른 세션에
선택해 첨부할 수 있습니다. 이 편집에는 모델 호출이 없습니다.

그래프는 분기와 합류, 선행 작업 이름, 조건·산출물 전달·실패 후 수정 연결을 표시합니다.
데스크톱에서는 화면에 맞추며 **크게 보기**로 원래 크기로 전환할 수 있습니다.
모바일에서는 글자 크기를 유지하고 그래프 영역 안에서 좌우로 이동합니다.
노드나 호출을 선택해야 상세 근거를 열며, 닫으면 전체 흐름으로 돌아갑니다.
대화의 날짜·시각과 호출 기록의 날짜·시각은 한국 시간입니다. 이전 대화를 읽는 동안
새 출력이 와도 스크롤 위치를 유지하며 **최근 대화**로 최신 위치에 돌아갈 수 있습니다.

과거의 LLM 관계·인계 정리와 명시적인 갱신은 호환으로 유지합니다. 해당 정리의
**작업 관계·근거 보기**는 모델 제안과 원문 근거를 표시합니다. **현재 대화로 정리 갱신**은
별도 모델 호출이며 자동 실행 허가가 아닙니다. 인계 자료를 정정하거나 받을 세션과
지시를 지정하는 기존 경로는 유지합니다. 저장한 정리는 일반 문답에 자동 표시하지 않습니다.

기존 LLM 제안의 수동 실행 경로에서도 웹에서 JSON을 직접 작성하지 않습니다. 실행할 근거가 갖춰진 계획에만 **이 계획으로 별도
격리 작업 시작**을 표시하며 수정 파일·검사 argv를 확인한 뒤 명시적으로 시작합니다.
프로젝트 package.json의 기존 test/check/lint 또는 Cargo.toml의 cargo test --jobs 1을
사용하고 모델이 새로 만든 임의 명령은 자동 실행 경로에 넣지 않습니다. 원래 세션이 작업 중이거나,
계획 뒤 코드·대화·자료가 바뀌었거나 미커밋 변경이 있으면 별도 실행을 거부합니다.
일반 세션을 읽었다고 기존 작업을 다시 실행하지 않습니다. 같은 실행 요청의 연속 클릭은
한 실행에만 연결합니다. 실행기 종료 후에는 **재개**로 저장된 결과부터 회수합니다.
전달이 불확실한 요청을 다시 시작했다고 표시하지 않습니다. CLI의 수동 명세 경로는 유지합니다.

CLI에서 실제 실행을 해당 지시에 연결하려면 `waga plan <세션 ID>`가 반환한 `workId`를
JSON 명세 최상위에 넣습니다. 다른 프로젝트에서 실행한다면 해당 지시의 작업 폴더를
`sourceCwd`에 명시해야 합니다. 폴더나 실행 시각만으로 기존 native 호출을 작업에 귀속시키지 않습니다.
연결한 실행은 지시 메시지에서 다시 열 수 있으며, 시도별 diff·산출물 SHA-256·기준 커밋·
실제 검사 argv/출력/종료 코드·검사 환경과 시각·독립 검토·작업자 보고를 보여줍니다.
이는 검사 당시의 근거입니다. 이후 변경까지 검증했다고 주장하거나 일반 세션의 응답을
완료·검사 통과로 바꾸지 않습니다. 기존 대화 전체를 소급해 작업으로 생성하지 않습니다.

1. `waga serve`를 실행합니다. 출력된 비밀 접속 링크는 본인 환경 변수에만 넣습니다.
2. 깨끗한 git 저장소의 신뢰하는 로컬 JSON 명세를 작성합니다. [작은 예제](../integrations/workflow.example.json)를
   복사해 제목·프롬프트·검사 argv를 실제 저장소에 맞추십시오. 검사 명령은 셸 문자열이 아닌 인자 배열입니다.
3. `WAGA_WEB_URL='http://127.0.0.1:4317/#접속비밀값' waga run ./workflow.json`을 실행합니다.
4. 웹에서 실행을 선택하면 작업 의존성, 검사·독립 검증·실제 호출이 갱신됩니다.

`sourceCwd`를 생략하면 웹 서버의 cwd를 사용합니다. 수정은 원본 커밋의 작업별 git worktree에서만
수행하고 원본 파일에 적용하지 않습니다. `inputs: [{from, path}]`는 선행 작업의 검증된 파일만
SHA-256을 대조해 복사합니다. `dependsOn`은 순서 제약이고 `outputs`는 수정 허용 파일입니다.
읽기 역할은 outputs를 선언할 수 없습니다. 통과한 작업은 재실행하지 않습니다.

Node 프로젝트는 작업자 호출 전에 원본에 설치된 `node_modules`를 작업별 독립 사본으로
준비합니다. package.json·package-lock.json이 원본과 같고 node_modules가 git 제외 대상일 때만
사용합니다. 사본은 최대 256MiB·10만 항목이며 원본 외부를 가리키는 링크는 거부합니다.
네트워크 설치나 설치 스크립트는 자동 실행하지 않습니다. 설치 부재·명세 변경·사본 불일치는
환경 준비 오류로 중단하며 모델 수정 재시도로 돌리지 않습니다. 로컬 설치를 복사한 것이므로
새 의존성 설치를 검증한 근거로 사용하지 않습니다.

기본 모델은 plan=opus, scan=haiku, edit/verify=sonnet이며 `models`에서 역할별로 지정합니다.
계획 모델도 선언된 plan 노드가 있을 때만 실행합니다. 작업마다 독립 검증은 별도 native 세션입니다.
작업자 성공·실제 검사 0·검증 pass·검증 중 산출물 불변을 모두 만족해야 통과합니다.
동일한 동작 검사·검토 실패가 두 회 연속 반복되면 재계획합니다. 패치 내용만 바뀌는 것은
진전이 아닙니다. 전체 최대 시도는 기본 5회입니다. 코드 결함은 수정 루프로, 명시적 권한
거절은 사용자 판단 대기로, 응답·전달 미확인은 기존 실행 회수로 분기합니다.
명세에 선언한 검사의 품질과 독립 검증 모델의 판단 정확도까지 보장하지는 않습니다.

기본은 순차 실행입니다. `maxParallel: 2`로 선언한 경우에만 의존성이 충족되고
입출력 파일이 겹치지 않는 작업 두 개를 함께 시작합니다. 추가 작업의 1.5GiB 메모리 몫도
확인합니다. 같은 runtime 루트의 서로 다른 실행들도 실제 프로세스 슬롯 두 개를 공유합니다.
파일 충돌·선행 결과·자원 부족이 있으면 순차 실행하거나 대기합니다. 모델을 호출해
파일·재시도·상태를 라우팅하지 않습니다. `providers`와 `models`의 역할별 명시 값이 경로입니다.
Linux에서는 사용자 systemd scope에 MemoryMax 1.5GiB, swap 0,
CPUQuota 200%, IOWeight 10과 nice 15를 적용합니다. scope 생성 실패는 실행 실패이며
제한 없는 재실행은 하지 않습니다. 비 Linux에서는 OS scope 제한을 제공하지 않습니다.
`/proc/meminfo`의 MemAvailable과 CPU 시간차를 읽어 기본 여유 6GiB·PC CPU 80% 이하일 때
시작하고, 실행 중 여유가 5GiB 아래로 내려가면 소유한 프로세스만 종료합니다.
웹의 자원 설정은 다음 검사부터 반영됩니다. 자원 대기 중에는 모델을 호출하지 않습니다.
CPU 사용률은 새 작업 시작 기준이며 실행 도중에는 2코어 scope 제한이 적용됩니다.
Claude는 호출별 CLI 비용 한도 $0.25와 보고된 누적 비용 $2 기준을 사용합니다.
Codex CLI는 같은 달러 상한을 제공하지 않으므로 비용을 미확인으로 남기고 보고된 토큰을
저장합니다. 두 제공자 모두 작업 시도 수·명령별 180초·자원 제한을 적용합니다.
중단으로 비용 보고가 유실될 수 있으므로 청구액의 절대 상한을 보장하지 않습니다. 과금은 각 제공자의 계정 정책을 따릅니다.

**일시정지**는 진행 중인 호출을 끊지 않고 다음 단계에서 대기합니다. **중단**은 소유한 실행
프로세스에 종료를 요청합니다. 브라우저를 닫아도 로컬 실행기는 계속됩니다.
이벤트는 전송 전에 ID와 함께 저장하고, 일시적 조회·이벤트 통신 장애는 동일 요청으로
최대 세 번 시도합니다. 새 실행 생성과 불확실한 모델 요청은 자동 재전송하지 않습니다. 서버 재시작 뒤
원래 포트에서 실행을 조회하고 `waga run ./workflow.json --resume 실행ID`로 남은 작업을 재개합니다.
중단 버튼으로 멈췄다면 웹의 **재개**도 먼저 누릅니다. 명세·원본 커밋이 바뀌었으면 재개를 거부합니다.
명령은 별도 소유 프로세스가 결과를 비공개 파일에 남깁니다. 실행기를 SIGKILL해도
재개 시 이미 완료한 작업자·검사·검토 결과를 먼저 회수하며 같은 명령을 다시 실행하지
않습니다. 응답을 잃은 이벤트도 같은 ID로 회수합니다. 잠금은 소유 PID의 종료를 확인하고
복구 경합을 막은 뒤에만 회수합니다. 소유권이나 결과를 확인하지 못하면 실행을 막고
원래 요청 확인을 요구합니다. PC 전원 종료로 요청의 실제 완료 여부까지 사라진 경우를
성공 처리하거나 자동으로 재전송하지 않습니다.

검사 근거는 커밋·작업 폴더의 diff·입출력 해시·검사 argv와 연결합니다. 검사·검토 중
대상이 바뀌면 통과하지 않습니다. 재개·최종 확인·종료된 실행 조회에서도 파일 변경을
대조해 이전 통과와 후속 의존 작업을 무효화합니다. 그래프는 받는 산출물·선행 검사와
독립 검토·대기 원인을 표시하고 연결된 작업의 실제 근거로 이동합니다. 관측 호출과
선언 의존성은 별개의 보기이며, 시간순 기록으로 선행 관계를 추측하지 않습니다.

전부 통과해도 **최종 검토 대기**에서 멈춥니다. **최종 검토 완료**는 확인 기록만 남기며
원본 적용·머지·배포를 실행하지 않습니다. diff와 검사·검증 근거를 먼저 확인하십시오.

실행 기록은 `runs`, credential과 worktree는 `runtime/실행ID`에 저장합니다.
기본 루트는 `$XDG_STATE_HOME/wattari-gattari`이며 파일 0600·디렉터리 0700입니다.
실행당 이벤트 2,000개·span 5,000개·저장 파일 8MiB, 산출물은 파일당 1MiB로 제한합니다.
실행별 bearer는 해당 실행의 이벤트·trace에만 접근하며 웹 제어에는 쿠키와 정확한 Origin이 필요합니다.
기존 세션·전역 설정·daemon은 변경하지 않습니다. Claude CLI는 restricted 모드와 명시적 도구 목록,
비활성 훅·MCP 설정으로 실행합니다. 기계 검사는 신뢰하는 로컬 명세의 명령을 실행합니다.

자동 실행은 Claude의 공식 print JSON과 Codex의 공식 exec JSONL 경계를 사용합니다.
`providers: {"edit":"codex","verify":"claude"}`처럼 역할을 지정할 수 있으며, 해당 제공자가
받는 모델 이름을 `models`에도 지정합니다. Codex는 사용자 설정을 변경하지 않고 해당 호출에서
`--ignore-user-config`, `approval_policy="never"`, 읽기 전용 또는 workspace-write sandbox를
사용합니다. 검토는 읽기 전용입니다. 파일 조회용 읽기 명령과 기계 검사 실행은 구분합니다.
Codex의 native thread ID·보고된 사용량과 Claude의 session ID·usage·보고된 비용을 같은
시도에 연결합니다. Claude Platform Console destination 설정은 별개입니다. 기존 모든 세션이 자동으로
계측되는 기능은 아닙니다. `includeContent: true`를 명시해야 span의 입력·출력·diff가 저장됩니다.
검사 출력·검증 사유·작업 diff는 실행 근거로 항상 저장합니다. 실행을 삭제하거나 worktree를
정리하는 자동 보존 정책은 제공하지 않으므로 필요한 근거를 확인한 뒤 별도로 정리하십시오.

## 실행기 실측 (2026-10-15)

폐기용 git 저장소에서 실제 Claude native 세션을 사용한 세 작업 실험을 수행했습니다.
독립 조사 A는 1회, 수정 B는 의도한 첫 검사 실패 뒤 2회, B 산출물을 받는 후속 조사는 1회
실행됐습니다. 통과한 작업은 다시 실행되지 않았고 세 작업의 별도 검증 세션이 모두 pass를
반환해 실행은 최종 검토 대기에 도달했습니다. 원본 파일은 변경되지 않았습니다.
최종 실험에서 62개 span, native CLI가 보고한 총 비용 $0.06347을 기록했습니다.
이는 작은 산술 예제의 흐름 검증이며 프로젝트 전체 수정 품질·비용 절감률의 측정은 아닙니다.

1초 간격 45회 샘플에서 PC 여유 메모리 최소 8.38GiB, CPU 최대 30.6%, 해당 실행 scope의
관측 메모리 최대 153MiB였습니다. 샘플 사이의 순간 최대값까지 보장하지는 않습니다.
별도 첫 실험에서는 여유 기준을 실제 RAM보다 높게 설정해 모델 미실행 대기를 확인하고,
웹 자원 설정을 6GiB로 변경해 진행시켰습니다. PC에 부하를 만들어 압박하는 실험은 하지 않았습니다.

자동 테스트는 실제 git worktree·검사 프로세스와 가짜 native JSON 응답을 결합해 무진전 중단,
검증 거절, 자원 압박 시 소유 자식 종료, 중단 후 남은 작업 재개, 인증 범위를 확인합니다.
브라우저에서는 실행·회차 근거, 데스크톱/390px 화면, 초안의 새로고침 복원과 A/B 수신자
격리를 확인했습니다. 초안 검사는 폐기용 가짜 세션 목록을 사용했고 기존 사용자 세션에는 보내지 않았습니다.
